# Скрипты сборки и проверки

| Файл | Что делает |
|---|---|
| `build-core-packs.mjs` | собирает «пакеты ядер» для установки без интернета (`npm run build:cores`) |
| `check-cores-bundle.mjs` | перед `npm run dist` проверяет, что пакеты для установщика собраны (запускается само, `predist`) |
| `compile-check.mts` | компилирует шаблоны через arduino-cli (`npm run check:compile`) |
| `e2e/` | сквозные тесты интерфейса, см. `e2e/README.md` |

## Ядра в комплекте: порядок сборки

```
npm run build:cores        # 1. один раз (нужен интернет): скачивает и собирает пакеты ядер
npm run dist               # 2. установщик (в него вкладываются AVR и ESP8266)
```

`npm run build:cores -- avr,esp8266` — только маленькие пакеты (≈ 200 МБ), без ESP32. `-- esp32 --no-zip` — без .zip.

Что получается:

| Пакет | Куда | Размер | Как попадает к пользователю |
|---|---|---|---|
| Arduino AVR 1.8.8 | `build/cores-bundle/avr/` | ≈ 75 МБ | внутри установщика → `resources/cores/avr/` |
| ESP8266 3.1.2 | `build/cores-bundle/esp8266/` | ≈ 133 МБ | внутри установщика → `resources/cores/esp8266/` |
| ESP32 (последняя 3.x из индекса) | `release/AVR-IDE-core-esp32-<версия>/` и `….zip` | ≈ 2,0 ГБ | отдельно: кладётся рядом с установщиком |

ESP32 в установщик не входит: NSIS не умеет файлы больше 2 ГБ, а с ESP32 установщик превысил бы лимит. IDE сама ищет внешние пакеты — папки `AVR-IDE-core-*` рядом с `AVR IDE.exe` (portable), рядом с папкой установки, в «Загрузках», на рабочем столе и в папке, которую пользователь указал кнопкой «Указать папку с пакетом…». Дистрибутив ESP32 можно отдавать папкой или `.zip` (распаковывается обычным проводником/7-Zip; сама IDE читает только папки).

### Устройство пакета

```
AVR-IDE-core-<id>-<версия>/
  manifest.json          id, package, arch, версия, индексы, список файлов с размерами и SHA-256, unpackFactor
  index/                 package_index.json (+ .sig), индекс платформы, library_index.json.gz (+ .sig)
  packages/              архивы платформы, её инструментов (toolsDependencies) и встроенных инструментов arduino-cli
```

Все файлы скачиваются строго по индексам пакетов (Windows x64: `x86_64-mingw32`, при его отсутствии `x86_64-w64-mingw32`, `i686-mingw32`), проверяются по размеру и SHA-256 из индекса и складываются в кэш `build/cores-cache/` (в `.gitignore`). Повторный запуск ничего не качает заново, оборванная загрузка докачивается. В пакет файлы попадают жёсткими ссылками на кэш (на одном томе диск не расходуется второй раз).

Индексы кладутся целиком (подпись официального индекса Arduino привязана к содержимому, а полный список версий нужен, чтобы «Обновить» и установка других версий работали как обычно). Встроенные инструменты arduino-cli (`builtin:ctags`, дискавери, монитор порта) и индекс библиотек входят в каждый пакет: без них arduino-cli при первом запуске лезет в интернет и сообщает об ошибке инициализации.

### Как IDE устанавливает пакет

1. Проверяет `manifest.json` (структура, пути без выхода за папку пакета) и свободное место (для ESP32 нужно ≈ 9 ГБ: архивы временно 2,0 + распаковка 6,9).
2. Проверяет размеры и SHA-256 нужных файлов (до любых изменений на диске пользователя).
3. Кладёт индексы в каталог данных arduino-cli, только если там нет подходящих (индексы пользователя без нужды не затираются); при необходимости добавляет адрес пакетов в `board_manager.additional_urls`.
4. Копирует архивы в `staging/packages` (пакет остаётся нетронутым; уже установленные инструменты не копируются).
5. Запускает обычный `arduino-cli core install vendor:arch@версия`: он находит архивы в staging, проверяет их контрольные суммы и устанавливает без сети. Получается нормальная установка: ядро видно в менеджере, его можно обновить и удалить.
6. Удаляет скопированные в staging архивы.

Если ядро этой версии уже установлено — IDE ничего не меняет.

## Проверка без интернета

Отключить сеть для arduino-cli можно переменной `ARDUINO_NETWORK_PROXY=http://127.0.0.1:1` (arduino-cli игнорирует `HTTPS_PROXY`). Так работают сценарии `m` и `n` из `e2e/` (`node scripts/e2e/run.mjs --only m`, см. `e2e/README.md`).
`AVRIDE_CORES_DIRS` — дополнительные папки поиска внешних пакетов (разделитель `;`), нужна для тестов.
