# Сквозные (e2e) тесты интерфейса

Запускают настоящее собранное приложение (Electron) и управляют им по Chrome DevTools Protocol:
клики и ввод — настоящими событиями мыши и клавиатуры, проверки — по DOM, файлам на диске и скриншотам при падении.
Зависимостей нет: свой клиент CDP на встроенном WebSocket Node 24 (`lib/cdp.mjs`).

## Запуск

```
npm run test:e2e                       # быстрые сценарии a–j, около минуты
npm run test:e2e:full                  # + k (компиляция ESP32), l (установка ядра, нужен интернет), m и n (ядра из комплекта без интернета)
node scripts/e2e/run.mjs --only c,h    # выбранные сценарии
```

Раннер сам делает `npm run build`, если исходники новее сборки. Для каждого сценария запускается отдельный экземпляр приложения.
Код возврата 0 — всё прошло. При падении в `scripts/e2e/artifacts` (в .gitignore) лежат `<id>.png` и `<id>.log`.

## Изоляция

- `--user-data-dir` и папка скетчей — во временной папке (`%TEMP%\avride-e2e-*`), настройки пользователя и `Documents\Arduino` не затрагиваются; папка удаляется после сценария.
- Окно открывается без захвата фокуса (`AVRIDE_E2E=1` → `showInactive()` в `src/main/index.ts`), ввод пользователя не перехватывается; страница при этом ведёт себя как активная (`Emulation.setFocusEmulationEnabled`).
- `AVRIDE_SIM_MONITOR=1` — имитация порта для монитора и плоттера.
- Каталоги arduino-cli (`ARDUINO_DIRECTORIES_DATA/USER/DOWNLOADS`): по умолчанию пустые временные; сценарии a–k, где нужны ядро и библиотеки, берут готовую среду `%TEMP%\ard2` (ядро esp32 2.0.17, ESPUI, Async TCP, ESP Async WebServer) и только читают её. Конфиг arduino-cli лежит в каталоге данных, так что глобальный не трогается.
- Процесс Electron закрывается по PID (`taskkill /PID … /T /F`), никогда по имени.

## Сценарии

| id | что проверяется |
|----|-----------------|
| a | старт: только «Создать проект»/«Открыть проект», нет панелей, шапки, строки состояния, горячие клавиши не действуют |
| b | мастер: поиск платы, выбор с установленным ядром, имя (ошибка для русского, ошибка занятой папки, корректное), создание: .ino во вкладке, `sketch.yaml` с `default_fqbn`, плата сверху |
| c | редактор: ввод, Ctrl+S пишет на диск, Ctrl+Space показывает `pinMode`, F1 на слове открывает справочник |
| d | конструктор ESPUI: элементы из палитры, привязка к `float temperature;`, «Вставить в скетч» → `ui_generated.h`, `#include`, `ui_setup()`, `ui_loop()`, `ui.json`; режим «Тест» |
| e | веб-дизайнер: блоки, ящик с HTML и C++, меню «Экспорт» |
| f | справочник: поиск `Serial.begin`, карточка, платы и распиновка (схема/таблица) |
| g | примеры: панель, поиск, «Открыть как проект» (копия в папке скетчей, оригинал в библиотеке не изменился) |
| h | поиск по проекту: Ctrl+Shift+F, найти, «Заменить всё» с подтверждением (отмена ничего не меняет), файлы на диске |
| i | монитор и плоттер на имитации порта: строки в мониторе, три линии в легенде, линии нарисованы на canvas |
| j | тёмная/светлая тема и ширина окна 1344 и 760: нет горизонтального скролла, элементов за краем окна, перекрытий кнопок шапки, заливок «не той» темы, Monaco в нужной теме (экраны: старт, мастер, проводник, поиск, примеры, платы, нижние панели, выбор платы, палитра, справочник, оба конструктора, настройки) |
| k | [full] компиляция ESP32: «Собрано · размер» в статус-баре; сломанный код → «Проблемы» → строка файла → красный маркер → клик ведёт к строке |
| l | [full] ПУСТАЯ среда: Arduino Uno в мастере → «Установить ядро» (реальная загрузка arduino:avr) → плата доступна → проект создаётся → «Проверить» собирает. Таймаут 10 минут, временные данные удаляются |
| m | [full] ПУСТАЯ среда и ПЕРЕКРЫТАЯ СЕТЬ (`ARDUINO_NETWORK_PROXY` на неработающий адрес): Uno и NodeMCU ставятся из встроенных пакетов ядер основной кнопкой «Установить из комплекта (без интернета)», в staging не остаётся копий архивов, проект NodeMCU собирается, раздел «Комплект» в панели «Платы» показывает пакеты установленными, отдельный `arduino-cli compile` для Uno проходит без сети. Нужны пакеты (`npm run build:cores`) |
| n | [full] то же для ESP32 из внешнего пакета `release/AVR-IDE-core-esp32-<версия>` (папка поиска задаётся `AVRIDE_CORES_DIRS`); без собранного пакета сценарий пропускается. Таймаут 45 минут |

## Чего тесты не проверяют

- Нативные диалоги ОС (выбор папки, «Открыть проект»): ими нельзя управлять через CDP. Открытие проекта проверяется через «Недавние» (список заранее записывается в настройки временного профиля).
- Загрузку на плату и реальный последовательный порт (платы нет): только имитация монитора.
- Внешний вид «на глаз»: проверяются геометрия и цвета фона, а не красота. Содержимое iframe-холстов (превью ESPUI и веб-дизайнера) в аудит темы не входит.
- Перетаскивание (drag and drop) из палитры на холст, жесты мыши внутри iframe-холстов.
- Установку ESP-ядер и подключение сторонних источников плат (сценарий l проверяет только arduino:avr).
- Упаковку установщика (`npm run dist`).

## Добавление сценария

Файл `scenarios/<id>-<имя>.mjs`, `export default { id, title, full?, arduino?: 'ard2' | 'empty', files?, projects?, timeout?, async run({ page, sketchbook, app, log }) }`.
`files` — заготовки в папке скетчей (`'Имя/Имя.ino': '…'`), `projects` — какие из них показать в «Недавних». Помощники: `lib/kit.mjs` (`openRecent`, `createProjectViaWizard`, `waitFile`, `editorText`, проверки), `lib/cdp.mjs` (`page.click`, `fill`, `key`, `waitFor`, `shot`, `setWindowSize`).
В коде, выполняемом внутри страницы (строки в `page.eval`), избегайте обратных косых черт в регулярных выражениях — пишите `[.]`, `[0-9]`.
Для поиска элементов используются `data-testid` (старт, мастер, шапка, активити-бар, нижние вкладки, вкладки редакторов, проблемы, конструктор ESPUI), остальное — по тексту, `aria-label` и классам.
