# Проверка AVR IDE: функциональность и интерфейс

Проверялась рабочая копия приложения в Electron на Windows. Результаты компиляции, симуляции и работы с физическим устройством не взаимозаменяемы.

## Воспроизведено и исправлено

| Проблема | Критерий проверки |
|---|---|
| **P0.** Холст мог вернуть удалённые вне IDE блоки в `web_design.json` при следующем автосохранении. Такой же риск был у ESPUI. | `ag`: A → B → A не смешивает черновики; внешняя версия обоих JSON остаётся на диске. Подключение веб-страницы при конфликте не создаёт заголовок. «Остаться в проекте» оставляет черновик для экспорта; после повторного открытия холст читает внешнюю версию. |
| **P1.** После выбора платы фокус иногда возвращался на чип поверх открытой командной палитры. `Esc` не закрывал её. | `s`: десять последовательностей «плата → Esc → Ctrl+Shift+P → Esc». Фокус попадает в поле палитры, затем палитра закрывается. `j`: полный прогон на 760 и 1344 px в обеих темах. |
| **P1.** На узком окне инспектор перекрывал переход в интерактивный режим веб-превью. На широком окне место занимали постоянные поля выбора шаблона и платформы. | `e`: при открытых свойствах «Попробовать» доступна, переключение освобождает холст. Платформа, шаблоны и новый проект сгруппированы в «Действиях». Подключённая страница предлагает «Обновить в скетче…», без подписи, похожей на индикатор ожидания. |
| **P1.** В пустом профиле мастер скрывал даже встроенный список плат до получения всех ответов CLI, включая список библиотек. | `b`: при ожидающей проверке можно найти Uno и выбрать плату. Получение списков плат и библиотек больше не ждёт друг друга; запросы JSON к CLI ограничены 20 секундами. Ограничение не применяется к самой установке и компиляции. |

Дополнительно через Electron: внутренние размеры окна 760/1280 px и эмуляция масштаба 125/150% в обеих темах; кнопки двух режимов, подключения и действий не перекрыты. Компиляция ESP32 прошла после перехода из «Проблем» к ошибке во втором файле и точечной правки. Редактор подхватывает внешнее изменение сохранённого `.ino`; отмена закрытия сохраняет локальный черновик, а после `Ctrl+S` и повторного открытия он загружается с диска. Автономный `page_bundle.html` скачан из веб-дизайнера и отрисован в пустом документе Chromium без служебной оболочки IDE.

В дереве доступности Chromium командная палитра представлена именованным диалогом с фокусом в поле поиска. В веб-превью `Tab` / `Shift+Tab` перемещают фокус между режимами, `Enter` переключает их. Собраны установщик и portable Windows x64; в собранном приложении есть CLI и манифесты AVR/ESP8266. Portable запущен с новым профилем и пустыми каталогами Arduino: при недоступной сети мастер предлагает AVR из комплекта.

`m` и `n`: Uno и NodeMCU установлены из встроенных пакетов, ESP32 3.3.12 — из отдельного. Во всех трёх случаях скетч скомпилирован без доступа к сети. Установка ESP32 заняла около 17 минут без учёта самой компиляции.

`l`: онлайн-установка Uno в пустом профиле прошла. После исправления встроенный список плат доступен сразу; индексы обновились, ядро установилось за 19 минут 28 секунд, мастер создал проект и IDE успешно скомпилировала скетч. Лимит установки в тесте увеличен до 35 минут: первый прогон оборвал корректно продолжавшуюся загрузку на старом 9-минутном лимите.

`xf`: реальный xPack ARM GCC 14.2.1 с проверенным SHA-256 и CMSIS собрал STM32F103C8, STM32F411RE и STM32G474RE. Проверены ELF/BIN/HEX, таблица векторов и размеры памяти; на F103C8 — также повторная сборка без лишней работы, отдельная сборка Release и переход от ошибки компиляции к `main.c`. Теперь все 32 E2E-сценария имеют подтверждённый успешный прогон (в нескольких запусках, а не в одном общем).

Поиск `ArduinoJson` без сети в пустом профиле показал сообщение об отсутствии связи примерно за 1,6 секунды и убрал индикатор ожидания. Когда тестовый прокси принимает соединения, но не отвечает, IDE показывает сообщение о таймауте примерно за 20,6 секунды. Успешную сетевую установку библиотеки эти тесты не подтверждают.

## Проверки вне этого стенда

В системе не обнаружены COM-порты или подключённые Pico / ST-Link / J-Link / CMSIS-DAP. Windows Sandbox и Hyper-V не включены. Эмуляция масштаба Chromium не заменяет проверку настроек масштаба Windows; проверка доступности клавиатурой и контраста оболочки не заменяет экранный диктор.

| Что нужно | Что принять как результат |
|---|---|
| Чистая Windows 10/11 x64 | Установщик и portable из текущей сборки; первый запуск без Node.js и Arduino CLI в системе; установка поддержки Uno без сети; компиляция; запуск после перезагрузки. |
| Uno, ESP32 и Pico | Скетч загружен на выбранную, а не предыдущую плату; получена новая строка UART и данные плоттера; Pico загружается через BOOTSEL, а CircuitPython записывает `code.py` именно на CIRCUITPY и не заменяет его при отмене. |
| ESP32 и ESP8266 | Страница открывается в обычном браузере. Изменение элемента доходит до скетча, изменение переменной возвращается в браузер. Отдельно проверить ESPUI и веб-дизайнер. |
| STM32 и программаторы | Пройти [аппаратный протокол](pro-hardware-test.md): запись ELF нужной конфигурации, breakpoint и шаг, перезапуск/отключение программатора, SWO. |
| Пользователи, экранный диктор, слабый ПК | Без подсказок пройти «первый Blink», «ошибка → строка → повторная сборка» и «веб-кнопка → переменная». Зафиксировать первый неверный шаг, неясный статус или потерю контекста. Проверить возврат фокуса и объявления состояний в Windows Narrator, а также отзывчивость Monaco при сборке и длительном UART. |
