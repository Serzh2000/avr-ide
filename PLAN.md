# AVR IDE — план разработки

IDE для Arduino (AVR) и ESP8266 / ESP32 / S3 / C3 с тремя главными частями:
1. Редактор кода и сборка/прошивка
2. Справочник по функциям и платформам
3. **Визуальный конструктор веб-интерфейса → генерация кода ESPUI** с привязкой к переменным

## Принятые решения
| Вопрос | Решение |
|---|---|
| Оболочка | Electron + Monaco Editor, Windows (потом Linux/macOS) |
| Сборка/прошивка | `arduino-cli`, поставляется внутри приложения |
| Конструктор | Дерево элементов ESPUI + привязка к переменным/пинам |
| Платформы v1 | AVR (Uno/Nano/Mega), ESP8266, ESP32 / S3 / C3 |

## Стек
- Electron + Vite + React + TypeScript
- Monaco Editor (C++ подсветка, автодополнение)
- Zustand (состояние), dnd-kit (drag&drop конструктора)
- serialport (монитор порта), arduino-cli через child_process (JSON-вывод)
- Справочник: статичные JSON/Markdown + поиск (MiniSearch)

## Архитектура
```
src/
  main/        Electron main: arduino-cli, файлы, serial, проекты
  renderer/
    editor/    Monaco, вкладки, дерево проекта
    reference/ справочник функций/платформ
    uibuilder/ конструктор, модель, генератор кода
    boards/    менеджер плат и библиотек
  shared/      типы, IPC-контракты
data/
  reference/   avr.json, esp8266.json, esp32.json
  espui/       описание виджетов (схема свойств)
```

## Модель проекта
Папка проекта = обычный скетч Arduino (`name.ino`) + `ui.json` (модель конструктора).
Генератор пишет в отдельный файл `ui_generated.h/.cpp`, чтобы не затирать ручной код.
Внутри — маркеры `// <<GEN BEGIN>> ... // <<GEN END>>`.

## Конструктор ESPUI (ядро продукта)
**Модель**: страница → вкладки (Tabs) → элементы. Каждый элемент:
`{ id, type, label, props, binding, direction }`

**Элементы (по актуальной версии ESPUI, список уточним при реализации)**:
Label, Button, Switcher, Slider, Number, Text, Select/Option, Graph, Separator, Pad, Tabs.

**Привязка (binding)** — главная фишка:
- **Выход (устройство → UI)**: элемент показывает значение переменной (Label, Graph, Gauge). Генератор пишет `ESPUI.updateLabel(id, String(var))` в таймере/цикле.
- **Вход (UI → устройство)**: callback элемента пишет в переменную (Switcher, Slider, Number, Button).
- **Пин**: Switcher → `digitalWrite`, Slider → `analogWrite`/`ledcWrite`, датчик → `analogRead`.
- Редактор переменных: имя, тип (`bool/int/float/String`), начальное значение, генерируется объявление в коде.

**Интерфейс**: слева палитра, по центру живое превью (как выглядит ESPUI), справа свойства и привязка, снизу вкладка «Сгенерированный код». Превью — эмуляция, ESPUI JS-фронт подключать не обязательно.

**Генератор**: модель → C++:
- `#include`, WiFi (STA/AP, SSID/пароль из настроек),
- объявление переменных, callback-и, `ESPUI.addControl(...)`, `ESPUI.begin(...)`,
- для ESP8266 и ESP32 учёт различий (библиотеки AsyncTCP vs ESPAsyncTCP).
- AVR: конструктор отключён (нет WiFi), показываем подсказку.

## Справочник
- Три раздела: AVR, ESP8266, ESP32 (+ S3/C3 отличия), плюс общий Arduino API.
- Карточка функции: сигнатура, параметры, пример, на каких платформах доступна, предупреждения (например ADC2 + WiFi на ESP32).
- Распиновка плат (картинка + таблица GPIO, особые пины strapping).
- Поиск по всему справочнику, «F1 на слове» в редакторе открывает справку.
- Источник данных: пишем вручную/полуавтоматически из официальной документации.

## Этапы
**Этап 0 — Каркас (1–2 дня)**: Electron+Vite+React, окно, Monaco, открыть/сохранить файл.
**Этап 1 — Рабочая IDE**: дерево проекта, вкладки, arduino-cli (поиск/установка ядер и библиотек, выбор платы и порта, Verify/Upload), панель вывода ошибок, монитор порта.
**Этап 2 — Справочник**: схема данных, UI, поиск, F1 из редактора, подсказки при наведении.
**Этап 3 — Конструктор MVP**: модель, палитра, превью, свойства, 4–5 виджетов (Label, Button, Switcher, Slider, Number), генерация кода, сборка на ESP32.
**Этап 4 — Привязки и полнота**: редактор переменных, пины, Graph/Select/Tabs, импорт/обратное чтение `ui.json`, несколько страниц.
**Этап 5 — Полировка**: темы, горячие клавиши, примеры проектов, инсталлятор (electron-builder), автообновление.

## Риски
- ESPUI зависит от версии библиотеки и ядра ESP32 (3.x изменил API LEDC) — генератор версионируем.
- Обратный разбор кода в модель не делаем: источник истины — `ui.json`.
- arduino-cli первый запуск скачивает ядра (сотни МБ) — нужен прогресс-бар.
- Автодополнение: начнём со словаря из справочника, LSP (clangd) — позже.
